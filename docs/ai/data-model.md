# Data model reference

Firestore Emulator内の主なコレクションと関係を、AIが調査・説明できる粒度でまとめます。これは代表フィールドの説明であり、
完全なTypeScript型の代替ではありません。フィールドを追加・削除する変更は、`src/types`、`functions/src/types.ts`、
rules、worker/Functions、関連画面を横断して確認してください。

## 1. 正本と派生データ

| 区分 | 例 | 意味 |
|---|---|---|
| 正本 | `users/{uid}`, `stocks/{stockId}`, `events/{eventId}`, `users/{uid}/transactions/{txId}` | 操作・約定・設定の基礎となるデータ |
| 派生 | `public_data/market_for_users`, `public_data/ranking`, `internal/price_engine` | 画面表示やworkerが使う計算済み状態 |
| 表示/コンテンツ | `news`, `news_presets`, `public_signages`, `video_library`, `image_library`, `signage_playlists` | 会場への伝達・演出 |
| 運用 | `admins`, `settings/*`, `schedule_sessions`, `riddle_rooms` | 権限、イベント制御、端末構成 |

派生データが一時的に遅れても、正本を直接書き換えて表示を合わせるのではなく、workerや再集計の経路を調査します。

## 2. 参加者と約定

### `users/{uid}`

代表フィールド:

| Field | Type/例 | 説明 |
|---|---|---|
| `uid` | string | Auth UID。ドキュメントIDと一致させる |
| `shortId` | string | 受付・QRで使う短い参加者ID |
| `nickname` | string | 画面表示名。重複し得るため識別子ではない |
| `points` | string/number | 取引に使うポイント。大きな整数を扱うため文字列保存があり得る |
| `inventory` | map | `stockId` -> 株数 |
| `totalAssets` | string/number | ランキング集計時点の総資産 |
| `courseType` | `TRADER`/`INSIDER` | 表/裏情報のコース判定 |
| `isFinished` | boolean | 最終確定状態 |
| `isTicketUsed` | boolean | 景品チケット使用済み状態 |
| `isInClass` | boolean | 教室在室状態 |
| `checkedInAt`, `checkedOutAt` | Timestamp | 在室操作時刻 |
| `lastAttendanceAction` | enum | `CHECK_IN`, `CHECK_OUT`, `PHASE_CHECK_OUT` |

`password`が旧データや管理ツールに存在しても、AIは値を読み上げたりエクスポートしたりしません。AuthパスワードをFirestoreへ保存する設計を増やさないでください。

### `users/{uid}/transactions/{idempotencyKey}`

約定履歴。`type` (`BUY`/`SELL`)、`stockId`、`price`、`amount`、`totalPoint`、`timestamp`、`isUndone`などを持ちます。
ドキュメントIDは冪等キーです。同一注文の重複を防ぐため、履歴IDを変えて再注文しません。

### `public_transactions/{idempotencyKey}`

サイネージや管理ログ向けの公開取引ログ。参加者画面へ不要な秘密情報を混ぜないよう、正本のサブコレクションと役割が異なります。

### `trade_quotes/{hash(uid, stockId)}`

Callableの短期見積もり。`uid`、`stockId`、`quoteId`、`price`、`issuedAt`、`expiresAt`、使用済み状態を持ちます。
数秒で期限切れになるため、保管して後から使うものではありません。

## 3. 市場と価格

### `stocks/{stockId}`

銘柄マスター。`id`、`name`、`currentPrice`、`basePrice`、`targetPrice`、`fluctuationPercent`、必要に応じて価格実行時刻。
管理画面の直接編集対象ですが、約定価格の最終決定はFunctionsです。

### `public_data/market_for_users`

参加者向けの派生市場。`stocks`配列、ランタイム補間用`runtime`などを持ちます。
公開画面のチャート・カードはここを優先して読む場合があります。手動で`stocks`だけ更新しても、公開表示が即時一致するとは限りません。

### `internal/price_engine`

価格フェーズ設定とランタイム状態。`configs[stockId].phases`、`runtime[stockId]`の`mode`、開始/終了価格、開始/終了時刻、seedなど。
一般参加者へ直接公開するためのデータではありません。

## 4. システム設定

### `settings/system`

代表フィールド:

- `globalPhase`: `STOP` / `RUNNING` / `EMERGENCY`
- `initialPoint`: 新規参加者の初期ポイント
- `initialHoldings`: 初期保有株
- `showInfoPageOnLogin`: ログイン直後Help表示
- `infoPageMarkdown`: 参加者Help本文
- `scenarioMode`: `AUTO` / `MANUAL`
- `ecoMode`: 家庭用/少人数向けのFirestore節約モード
- `tradeQuoteRequired`: 見積もりなし旧形式注文を拒否する移行フラグ
- `tradeQuantityPresets`: 取引数量ボタン
- `loopEnabled`, `loopIntervalMinutes`, `loopScenario`: シナリオループ
- `schedules`: STOP/RUNNING/EMERGENCYの時刻予約
- `emergencyState`: 緊急演出と価格処理の時刻・適用状態
- `clientVersion`: 端末へキャッシュ再読み込みを促すバージョン

### `settings/prizes`

`grades`配列に景品ランクID、閾値、説明を保存します。閾値とポイントの単位を混同しないようにします。

### `settings/classroom_operation`

教室表示・対象者・運用モードの状態。UIの型と保存形状が拡張される可能性があるため、未知フィールドを勝手に削除しません。

## 5. シナリオ・ニュース

### `events/{eventId}`

代表フィールド:

- `time`: 絶対時刻。`null`の場合はセッション/offset運用の可能性。
- `offsetSeconds`: セッション内の相対時刻。
- `sessionId`: `schedule_sessions`への参照。
- `priceChanges`: 銘柄ごとの確率分岐配列。
- `publicNewsPresetId`, `postNewsPresetId`, `insiderNewsPresetId`: プリセット参照。
- `postNewsDelaySeconds`: 事後ニュースの遅延。
- `signageTargetId`: 演出を出す一般モニター。
- `selectedBranches`: 実行時に選ばれた分岐。
- `processedParts`: `main`/`postNews`の部分処理済み状態。
- `isProcessed`: 完全処理済みか。
- `isAutoGenerated`: ループ等から生成されたか。

過去データには旧形式の自由入力ニュースや旧サイネージフィールドが残る場合があります。新しい編集画面はプリセット参照を優先します。

### `news/{newsId}`

配信済みニュース。`title`、`body`、`stockId`、`target` (`ALL`/`INSIDER`)、`kind` (`PUBLIC`/`POST`)、`timestamp`など。
これは参加者が読む履歴であり、プリセットの編集内容を直接反映するテンプレートではありません。

### `scheduled_post_news/{id}`

事後ニュースの配信待ち。`isDelivered`をworkerが処理します。未配信を直接`news`へコピーせず、スケジューラ/workerの条件を調査します。

### `news_presets/{id}`

`name`、`title`、`body`、`breakingVideoId`、`signageDisplay`（モード、時間、動画、NORMAL/AD）を持つ再利用テンプレート。

### `schedule_sessions/{id}`

`name`、`startAt`、`endAt`、`order`。シナリオの時間軸をグループ化します。金曜午前を自動探索する特別処理はありません。

## 6. サイネージとメディア

### `public_signages/{id}`

一般モニターの名前、モード、自動/手動オーバーライド、プレイリスト、現在表示などを持ちます。公開表示画面はIDでこのドキュメントを読むため、ID変更は配布済みURLへ影響します。

### `riddle_rooms/{id}`

謎解き部屋の名前、テーマ、TV roles、演出steps、現在ステップ、タイマー、受付/進行状態など。複数端末が同じ部屋ドキュメントを購読します。

### `video_library/{id}`

`name`、`videoAsset`、`volumeGain`、`groupId`、作成/更新時刻。動画本体はStorage Emulator由来のローカルアセット表現です。

### `image_library/{id}`

`name`、`imageAsset`、`source` (`upload`/`template`)、`templateId`、作成/更新時刻。

### `signage_playlists/{id}`

`name` と順序付き `items`。アイテムは動画・画像・株価/ニュースなどの表示プリセットを表します。

## 7. 権限とデータ境界

- Authのログイン有無は、Firestoreドキュメントの所有者/管理者権限とは別の層。
- 参加者は自分のUIDのデータを中心に読む。管理者は画面とFunctionsでロールを検証する。
- サイネージは公開読み取りが必要な状態だけを読む。管理用の`internal`や個人データを表示へ混ぜない。
- Storage EmulatorのアセットURLは、インターネット上の公開URLと同じ扱いにしない。Dockerのホスト/ブラウザから到達できる範囲を確認する。

## 8. AIのデータ操作ルール

1. Firestore Emulatorであることを確認するまで、データ変更コマンドを提案しない。
2. 変更前に対象コレクション、ドキュメントID、既存値、期待する結果、復元方法を記録する。
3. サブコレクションの履歴を削除して「表示を直す」ことをしない。
4. 派生データの不整合はworker/再計算を調査し、正本を書き換えて合わせない。
5. 参加者情報を含む出力は最小限にし、ログ共有時にID/名前/メールをマスキングする。
