# Reusable AI prompts

この文書は、運営者・開発者がAIへ依頼するときの定型文です。MCPの`prompts/get`からも同じ趣旨のプロンプトを取得できます。

## アプリを理解させる

```text
このリポジトリのAIコンテキストを最初に読んでください。
AGENTS.md -> docs/ai/README.md -> concepts.md -> screens.md -> operations.md -> data-model.md の順です。
私の目的は: [目的]
対象は: [URL、画面、端末、イベント、銘柄、参加者ID]
まず、関係する役割・画面・データ・不変条件を要約し、まだ操作はしないでください。
```

## イベント準備

```text
イベント開始前のチェックリストを作ってください。
対象日/会場: [記述]
利用端末: [参加者/受付/証券窓口/一般モニター/謎解きTV]
シナリオ: [AUTOまたはMANUAL]
既に確認済み: [項目]
未確認: [項目]
破壊的操作は提案だけにし、実行前に対象と影響を確認してください。
```

## 取引トラブル

```text
取引トラブルを調査してください。
参加者短いID: [マスキング可]
銘柄: [銘柄]
発生時刻: [時刻]
画面: [参加者画面/証券窓口]
表示エラー: [文言]
履歴に見える状態: [成功/不明/失敗]
まず quote・冪等キー・履歴・残高を確認する順番を示し、同じ注文を新しいキーで再送する提案はしないでください。
```

## サイネージトラブル

```text
サイネージを調査してください。
対象URL: [idまたはroomId/roleを含むURL。秘密情報は除外]
端末台数: [1台/複数]
症状: [黒画面/古い表示/動画なし/音声なし]
管理画面での設定: [モニター、プレイリスト、動画、部屋、役割]
まずURL、Firestore Emulator接続、アセット参照、IndexedDBキャッシュの順で切り分けてください。
表示中のリロードやキャッシュ削除は、演出中断の影響を説明して確認を取ってください。
```

## コード変更レビュー

```text
次の変更をStock League Event Localとしてレビューしてください。
変更: [差分の要約]
影響する画面/Functions: [記述]
確認したいこと:
- 参加者/terminal/general/core/public signageの権限境界
- 取引のサーバー正本、quote、冪等性
- 正本と派生データの区別
- ローカルEmulator限定の前提
- サイネージ長時間稼働とPWAキャッシュ
- destructive operationと復元
- AI context packの更新要否
最後に、docker compose config -q、build、テスト、手動確認を具体化してください。
```

## 事故対応

```text
これはインシデントです。推測でデータ変更せず、次のフォーマットで回答してください。
観測:
影響範囲:
止めるべき操作:
追加で取得する安全な証拠:
暫定案内:
復旧案（可逆 -> 高影響の順）:
人間の承認が必要な操作:
復旧後の検証:
```
